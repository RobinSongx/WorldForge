# P1.1：静态 GLB 导入与基础编辑

日期：2026-09-20。状态：实现已落地并通过 CPU/GPU 自动测试；原生文件选择交互待人工验收。实施基线：8de2a30。
结果见 [实现说明](../learning/0002-mesh-import.md) 与 [验证记录](../benchmarks/2026-09-20-mesh-import.md)。以下保留批准时的范围与方案。
本任务是 P1 Mesh 系统的第一个可体验增量，不代表完整 P1 或首期已完成。

## 今晚目标

从 Windows 界面选择一个受支持的 GLB，导入后看到真实几何，
在 Scene 中选择模型，调整整体位置/旋转/缩放，显隐、删除并定位相机。
导入失败保留原场景，程序继续可用。

## 交付边界

| 能力 | 今晚交付 |
| --- | --- |
| 输入 | 单个自包含 glTF 2.0 GLB；从菜单打开 Windows 文件选择框 |
| 几何 | 静态 TRIANGLES；多 mesh、多 primitive；有索引和无索引三角形 |
| 顶点 | FLOAT POSITION/NORMAL；读取常规 TEXCOORD_0；正确处理 accessor offset/stride |
| 索引 | 8/16/32 位无符号索引，验证范围后统一为运行时 32 位索引 |
| 场景 | 导入默认 scene；未指定默认值时使用第一个 scene；没有 scene 则明确失败 |
| 节点 | 保留节点名称、父子关系和 matrix/TRS；重复 mesh 引用共享 CPU/GPU 几何 |
| 编辑 | 每次导入新增一个可编辑根对象；内部节点可展开查看，暂不单独编辑 |
| 材质 | 使用 baseColorFactor 与现有基础光照；贴图/PBR 效果不显示并明确提示 |
| 相机 | 导入成功后按世界包围盒取景；F 定位所选模型，不再以 Cube 缩放估算 |
| 导入状态 | 最小单任务后台解析；显示阶段状态，成功/失败/警告可查看 |
| 发布物 | 可运行开发构建、测试记录、实现说明和代码提交；本任务不自动新增 Release |

仍支持现有 Cube，改为使用同一 Mesh 数据/上传/绘制路径。
重复导入创建独立根对象；跨次导入按文件内容去重不进入今晚范围。
“支持常规 TEXCOORD_0”指读取 FLOAT 或归一化无符号 8/16 位 VEC2，
并保留数据，不代表已实现贴图采样。

## 明确的格式限制

- 暂不支持 .gltf + 外部资源；GLB 不读取外部 buffer/image URI。
- 暂不支持动画、蒙皮、morph、稀疏 accessor、压缩或量化几何，以及点/线/strip/fan primitive。
- 遇到上述结构、未知必需扩展、损坏数据或透明材质，明确拒绝本次导入，不静默删除内容。
- 贴图和 metallic/roughness 等外观参数本轮只报告未呈现，不称为完整材质还原。
- 缺失法线可生成临时平面法线并提示；不修改源文件。无法生成有效法线的退化三角形明确报错。
- 节点索引、父子关系、循环引用、数据区间和乘加溢出均需校验。
  非有限顶点、非法索引、不可逆节点变换或空几何有明确诊断。
- 保留 GLB 右手坐标和原始尺寸，不自动旋转、居中或缩放源几何。
  通过移动相机完成取景；不把“模型看起来居中”实现成篡改资产。

## 数据与代码方案

只新增当前功能需要的模块，不一次铺开完整架构。

| 位置 | 职责 |
| --- | --- |
| src/domain/mesh_asset.* | CPU 顶点、primitive、索引、基础材质、AABB；不依赖 SDL/GL/格式库 |
| src/domain/imported_scene.* | 不可变导入结果：mesh 集合、节点树、节点局部矩阵与诊断 |
| src/io/glb_importer.* | 从内存字节解析 GLB，校验并转换成自有数据；隐藏 tinygltf 类型 |
| src/application/import_service.* | 单任务状态、完成结果、场景代次；不直接调用 GL |
| src/platform/ | 文件选择与 UTF-8 文件读取适配；回调只提交路径消息 |
| src/editor/ | 新增导入根对象、资产引用、整体编辑和取景；场景仅在主线程修改 |
| src/render/ | 按资产 ID 缓存 VBO/EBO/VAO，消费只读绘制列表 |
| src/ui/ | Import GLB、节点树、根对象属性、导入状态和诊断 |

CPU 资产由场景资产存储持有；实体引用资产，不复制整份顶点。
GPU 缓存由 Renderer 持有；删除最后一个引用或 New Scene 后回收对应资源。
ID 暂为当前会话稳定 ID，不能作为持久化 ID 对外声明；UUID 与项目保存一并落实。

每个导入模型有一个用户可编辑的包装根变换。
原文件节点矩阵保持只读，不强行分解为现有 Euler Transform：
最终模型矩阵 = 包装根变换 × 祖先矩阵链 × 当前节点局部矩阵。
由此保留 matrix/TRS、层级与共享实例的原有关系。
原始局部 AABB 的八个角变换后合并为世界 AABB，用于取景与统计。

Renderer 的新增 Mesh 绘制入口接收最小只读列表：
资产引用、模型矩阵、基础颜色、显隐及选中标识。
不为今晚引入完整 RHI、通用 Command 框架或插件接口。

## 依赖与线程方案

沿用路线图中的 tinygltf，拟采用目前主线 v3 的 C API，
在自有 C++ 适配层转换成 domain 数据。它尚未加入本仓库；
第一步必须先验证 MSVC 编译、内存 GLB 解析、显式错误与释放路径。
通过后固定精确提交并补第三方声明，不跟随浮动分支。
如果验证发现阻塞，记录原因并调整计划，不静默更换库。

平台文件读取与格式解析分开，Importer 接收字节，不调用 SDL 或打开窗口。
使用最小单工作线程；一次只接受一个导入，忙时禁用重复提交。
状态显示“读取 / 解析与校验 / 等待上传 / 完成或失败”，没有真实进度时不显示虚构百分比。

文件对话框回调可能来自其他线程；立即复制路径到受控消息队列，
回调中不访问 EditorState、ImGui 或 GL。
工作线程只产生独立 CPU 结果；主线程检查场景代次后准备 GPU 上传并发布根对象。
New Scene 或退出会使待发布结果过期，旧任务不得附着到新场景。
退出等待正在执行的工作结束并安全释放回调上下文；今晚不承诺硬中断解析。
GL 上传和销毁只在主线程、有当前上下文时执行。

发布前完成全部解析、校验和所需上传；失败释放本次临时结果，
既有场景不变。不要求搭建完整事务框架。
以小型样例验收；解析放到后台不等于上传零卡顿。
记录文件大小、导入阶段耗时、顶点/三角形数和上传字节数，
遇到实测卡顿再决定下一步分批上传，不在今晚承诺大型场景吞吐。

## 实施顺序

1. **解析验证与数据契约**：固定 tinygltf 提交；自造最小 GLB 在 CPU 测试中解析成功和失败。
2. **Mesh 渲染接通**：把 Cube 移入通用 Mesh 路径；支持索引绘制、多个 primitive 和几何共享。
3. **导入与界面联通**：文件选择 → 工作线程 → 主线程发布 → 节点树 → 根对象编辑 → AABB 取景。
4. **验收与交付**：失败隔离、资源释放、真实 GPU 检查、构建、文档和提交。

若时间不足，保留已验证的完整步骤并明确剩余事项；
只有“界面选文件后成功显示并编辑模型”通过，才能宣称今晚目标完成。
PBR、贴图、项目保存、多平台、Gaussian、CLI/Agent 和插件不追加到本任务。

## 验收条件

- 自造 GLB：有/无索引、offset/stride、多 primitive、共享 mesh、多层节点与 matrix/TRS。
- 导入一份允许使用的真实静态模型；正确显示与取景，根对象移动/旋转/缩放有效。
- 原有 Cube 与导入模型共存，分别选择、显隐、删除；New Scene 后仍能再次导入。
- 中文路径与取消文件选择正常；取消选择不改变场景。
- 损坏文件、越界索引、不支持的必需扩展、稀疏/动画等输入明确失败，旧场景可继续编辑。
- 导入期间 New Scene、连续点击导入或关闭窗口，不出现过期结果、悬挂指针或错误 GL 访问。
- GPU 测试确实使用导入几何，验证非空画面、resize、变换和资源生命周期；
  不以现有 Cube smoke 替代 Mesh 验收。
- Google 风格检查、Windows Release 构建、CPU 测试、相关 GPU 检查通过。
  .cpp/.h、函数空行、核心中英文注释继续执行。
- docs 更新实现边界、验证命令与样例来源；不将本计划当作已实现能力。
