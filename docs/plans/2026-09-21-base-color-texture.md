# 今晚任务：选择显示与基础颜色贴图

日期：2026-09-21。状态：待执行计划，尚未实现。
定位：0.0.3 Mesh/Scene 闭环的第一个增量；不是完整 0.0.3，也不新增正式 Release。
代码基线：4f0d5f9。新版路线图文档仍有未提交改动，实施时保留并单独整理。

## 1. 今晚的结果

导入现有 Duck GLB 后，看见其基础颜色贴图；选中模型仍能编辑，但可以独立关闭黄色三角线。
按约 3–4 小时的开发窗口规划，优先交付可运行、可验证的完整切片，不把时间估计作为完成承诺。

已核对：现有小鸭样例是嵌入 BIN 的 PNG，使用 TEXCOORD_0、repeat 和 mipmap 过滤；当前代码保留 UV，但只渲染 baseColorFactor × Tint，并自动叠加选中线框。

## 2. 必做范围与顺序

| 顺序 | 任务 | 预估 | 结果 |
| --- | --- | --- | --- |
| 1 | 选中显示与取消选择 | 25–40 分钟 | Ground Grid、Wireframe、Selection Overlay 三者独立；可清空选择 |
| 2 | 最小材质/图片数据与 PNG 解码 | 45–65 分钟 | GLB 图片字节 → 后台解码 → 不可变 CPU 图片与材质引用 |
| 3 | GPU 纹理上传与基础颜色采样 | 50–70 分钟 | Duck 原始基础色显示；保留 Tint 和现有漫反射预览 |
| 4 | 回归验证、文档、开发包与提交 | 45–65 分钟 | CPU/GPU 检查、真实模型截图、可运行程序与验收记录 |

合计约 2 小时 45 分钟至 4 小时。遇到解码依赖或颜色管线问题，优先保留验证时间，明确未完成项，不用增加通宵范围换取表面完成。

### A. 选择显示

- 增加 Selection Overlay 独立开关，建议默认关闭；Scene 高亮和 Inspector 仍标明当前选择。
- Grid 只控制地面网格；Wireframe 控制全部几何的线框模式；Selection Overlay 只控制选中叠加。
- 增加明确的 Clear selection 操作；Scene 面板空白处单击和受限上下文中的 Esc 可清空选择。
- Esc 只在 Scene/Viewport 聚焦、未输入文本且无弹窗时处理，不抢文件对话框、文本编辑或弹窗关闭事件。
- 今晚不增加视口拾取。因此“点击空白清选”仅指 Scene 面板，不能把点击视口任意位置都当作空白。
- 清空选择不删除实体，不改变变换；F/Frame、Inspector 在无选择时安全退化。

### B. 贴图最小闭环

必做：自包含 GLB 中的嵌入 PNG baseColorTexture + TEXCOORD_0，现有 OPAQUE 静态 Mesh。
不含外部文件、data URI、UV1、texture transform、压缩纹理或 alpha 混合。

- domain 增加最小图片、采样参数和材质引用；保持无 SDL/GL/格式库依赖。
- 图像解码在导入工作线程执行。采用可固定版本的轻量解码实现，先验证内存输入、显式错误及许可证，不临时引入平台专属图片对象。
- 校验 bufferView、MIME、实际编码、尺寸、通道、解码字节乘法与单图/累计资源上限；执行时在引入解码器前确定具体限额。
- 一份导入资产内同图共享 CPU 数据，GPU 资源支持同图不同采样参数；重复实例不重复上传。
- 遵循源 sampler 的常用 wrap、min/mag 与 mipmap 设置，包括当前 Duck 的过滤配置。
- 明确基础色纹理、颜色因子、灯光计算与最终显示之间的颜色空间转换；不能直接在现有 shader 上乘一张纹理而忽略显示编码。UI 合成避免重复转换。
- 保持 UV 约定一致，以非对称测试图验证方向，不凭小鸭整体颜色判断是否正确。
- 没有贴图继续使用基础色；已有 Cube 继续显示。
- 被引用的损坏 PNG、非法 sampler/UV 或尚不支持的基础色纹理组合，明确失败并保留旧场景，不显示错误结果冒充成功。
- 未实现的其他材质通道继续给出准确警告；PNG 贴图成功后不能再一概提示“所有贴图未显示”。

JPEG 为可选加项，只有 PNG 全链路与必要测试完成后才考虑；没有实现时明确提示不支持，不能声称支持全部 glTF 核心图片格式。

### C. Inspector 与统计

显示基础色贴图是否存在、图片尺寸和采样状态；没有贴图也有明确状态。
Performance 区分几何缓存与纹理缓存的数量/估算字节，不把它们称为驱动总显存。
材质面板保留模型 Tint；不在今晚开放完整材质编辑器。

## 3. 生命周期与失败边界

沿用现有事务顺序：读取/解析/解码 → 主线程检查场景代次 → 几何及纹理暂存上传 → 全部成功后发布实体。
GL 资源只在主线程和当前上下文中创建/销毁。任一上传失败清理本次临时资源，不影响已导入场景。

删除最后引用或 New Scene 后回收对应纹理；隐藏模型不回收仍在使用的资产。
导入中 New Scene/退出延续现有代次隔离和 join 规则，不另造任务框架。

## 4. 验收

1. 小鸭显示基础颜色贴图；关闭 Selection Overlay 后黄色三角线消失，模型仍保持选中、可编辑。
2. Grid、Wireframe、Selection Overlay 的组合行为独立；清空选择后 Inspector 正常，无误删/误移动。
3. 非对称颜色测试图验证 UV 方向、Tint 乘法、颜色转换与 sampler；单纯“有非背景像素”不算贴图正确。
4. 多 primitive、共享图片/实例、无纹理 Cube 共存；删除、New Scene、重新导入无纹理泄漏。
5. 损坏图片、越界引用、超尺寸/预算及不支持的 UV/格式有明确失败，旧场景仍可渲染。
6. 保留现有索引、节点、任务生命周期和 GPU smoke 回归；新增贴图上传/采样/释放的必要 CPU/GPU 用例。
7. 执行 Google 风格检查、Windows Release 构建和相关测试；C++ 使用 .cpp/.h、函数空行、核心中英文注释。
8. 更新 docs 验证记录、安装开发包并检查实际模型；提交代码及相关文档，不自动创建正式 Release。

原生文件选择的完整自动验收仍有环境欠账：之前 Computer Use 初始化失败。本轮可重试；若仍不可用，记录未验证项，不能以程序化导入测试冒充原生选框已通过。用户此前截图已经证明一次正常界面导入成功，但未覆盖取消/关闭等边界。
