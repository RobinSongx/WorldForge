# ADR 0005：Scene 外部引用文件与事务重开增量

2026-09-28 实施更新：用户已授权开发，第一增量已落地；具体实现取舍、验证证据及未验项见 [实现说明](../learning/0004-scene-save-open.md) 和 [验收记录](../benchmarks/2026-09-28-scene-save-open.md)。下文保留 9/21 设计基线，不作为最新运行状态声明。

日期：2026-09-21。状态：设计提案，尚未实现；用于下一轮 Scene 保存/重开。
依据：用户先做方案设计，沿用 Windows 优先与 0.0.3 的 Scene 闭环目标。
详细契约见 [Scene 保存与重开方案](../plans/2026-09-21-scene-save-open.md)。

## 决策

1. 先交付 .wfscene UTF-8 JSON v1 + 外部自包含 GLB 引用；不序列化几何/纹理/GPU 数据，不自动复制源资产。
2. 场景、资产记录、实体使用持久 UUID；运行时句柄和 GPU 缓存 ID 独立。场景实体以 asset_id 共享资产，不按路径猜测身份。
3. 路径默认相对场景目录，Save As 重算基准；跨盘使用显式 absolute 引用。允许外部 ../ 引用，但不声称它具备封闭项目包的可携带性或沙箱语义。
4. 保存 GLB 完整内容 SHA256 与 importer profile；Open 和 Save 校验来源版本，变化/缺失明确失败，不静默替换资产内容。
5. Open 对 CPU 文档和全部 GPU 资源做整体准备，成功才替换当前场景；失败保持旧世界。首版不做缺失资产占位。
6. Save 使用同目录临时文件、完整写入/flush、平台替换和备份恢复；返回“未提交/已提交/需要恢复”，不把所有系统错误都当作旧路径必定未变。
7. 会话持有单写者租约，同时检测非协作外部修改；文件 API、宽字符路径、hash/UUID 平台实现不进入 domain。
8. 相机/显示作为可选 editor_state 随显式 Save 同文件记录；它们不递增业务 revision，导航也不触发世界脏提示。布局/选择不保存到场景。
9. 收敛文档修改入口以追踪 dirty；不同时建设完整 Undo、CommandRegistry、Agent 或通用 Job 框架。

## 与既有架构草案的关系

| 长期条款 | 本增量的暂定收窄 |
| --- | --- |
| 项目目录、复制依赖、禁止越界引用 | 本轮是外部引用场景文档；封闭可搬移项目包后续单独实现 |
| 相机等编辑状态另存 | 暂放可选 editor_state 区块，仍与世界语义、revision 分离；未来发布/导出场景可省略 |
| 缺失资产保留 Entity 占位 | 首版整次打开失败；后续恢复/重定位 UI 再引入占位策略 |
| 任意仿射世界变换/父子层级 | v1 保存当前包装根 TRS；源 GLB 矩阵保留在源资产中 |
| 持久 EntityId 替代会话整数 | 明确持久身份与会话选择句柄双轨，文件只写 UUID |
| nlohmann/json、Catch2 候选 | 首选已固定的 JSON C API，保留现有测试工具；探针验证后再落地 |

这些是增量设计建议，不把 ARCHITECTURE 的长期接口草案当成本轮必须一次实现的清单。也不降低 ROADMAP/PHASE_1 的完整项目搬移、基础撤销和最终 Hybrid 验收要求。

## 代价与未承诺

源文件被移走/改变时，外部引用场景可能打不开；首版没有自动修复路径。Open 保留旧场景会增加 CPU/GPU 峰值，按候选预算拒绝而不提前清空旧世界。

未实现只读打开、多用户协作、网络盘、项目依赖复制、自动保存、进程断电绝对持久保证。Save As 保持逻辑身份，不是独立世界的 Fork。

是否进入实现以用户下一步指令为准；本 ADR 与示例格式只是可评审设计，不构成运行能力声明。
