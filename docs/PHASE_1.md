# 首期交付：Windows Hybrid World Studio（v0.1）

日期：2026-09-21。状态：v0.1 尚未完成，当前为 0.0.2-texture-dev，已支持 PNG 基础色与独立选择显示。本文件只定义 Windows 首发，不代表全部面试前 P0 能力；后续 v0.2/v0.3 范围以 ROADMAP 和 ADR 0004 为准。

## 1. 首期目标

在 Windows 上完成“导入已有 Mesh/Gaussian 资产 → 检查与对齐 → 场景组合与混合显示 → 保存项目包 → 搬移/重开”的世界资产闭环，并发布可运行客户端。

首发目标为 ROADMAP 的 v0.1。先完善 Mesh/Scene，再混合渲染与项目闭环。保留 GPU 基线，为 v0.3 的必交优化提供对照；Linux 核心构建提前，但 Linux 桌面发布、CLI/Agent 和插件不阻塞 Windows v0.1。

## 2. 必须交付

| 子系统 | 首期范围 | 验收证据 |
| --- | --- | --- |
| Windows 桌面 | SDL3、ImGui docking、GL 4.5、DPI/输入/resize、相机、日志、释放资源 | Windows 干净构建和解压运行检查 |
| Mesh | 静态三角形 GLB、材质/纹理、节点层级/实例、不透明 metallic-roughness PBR | 多材质与共享实例样例正确显示 |
| 编辑 | 场景树、选择、显隐、创建/删除、变换编辑、基础撤销；不可分解矩阵保留 | 编辑与保存重开一致 |
| 调试 | PBR/线框/法线/包围盒，Mesh/GS 显示切换 | 固定相机可比较与定位问题 |
| Gaussian | 支持明确约定的 3DGS PLY，位置/旋转/尺度/opacity/SH 转换，实体变换 | 导入实际资产并报告不支持或损坏数据 |
| 混合渲染 | Windows/NVIDIA CUDA provider，共享相机、线性深度、透明贡献合成 | Mesh 位于 Gaussian 前/后/交叉三类用例与限制说明 |
| 世界组织 | 可移动 Mesh 与 Gaussian 根实体、手动尺度/轴向对齐、可选碰撞代理/语义关联 | 同一 Entity 的 Visual/Collision 独立显示；不假装完成物理仿真 |
| 基础检查 | 索引/非有限数据/退化面、法线或纹理缺失、Gaussian 参数合法性 | 资产级诊断；不静默修复或丢失源数据 |
| 项目包 | JSON、相对路径、源/派生分离、完整复制 GLB/PLY 及依赖、原子清单保存 | 原始导入位置不可用时仍可打开搬移后的混合项目 |
| 后台任务 | 导入进度、尽力取消、过期结果隔离、GPU 上传状态 | 取消/切项目不误附着，失败不会破坏旧项目 |
| 性能与发布 | 基础/分段计时、按瓶颈优化、Windows 包与样例、可复现演示 | 按 ROADMAP 固定条件记录帧时/显存和功能验收 |

发布包需区分 Mesh 能力与 NVIDIA 混合渲染要求。未启用/不可用 CUDA 时客户端仍可查看 Mesh，明确提示 Gaussian 不可用；不能静默显示空背景。首期混合体验的验证硬件是 RTX 4070 Ti，不承诺其他 GPU 已验证。

## 3. 现在只保留的架构边界

Core 不依赖 UI，场景修改走业务服务/命令；文件适配器、图形资源、Gaussian provider 与任务保持分离。这些边界服务当前实现，也让后续 CLI、插件和平台移植可以接入。

不提前实现公开 SDK、完整命令 schema 发现、远程协议、命令收据或第二渲染后端。RHI 只封装实际需要的资源和调用，不要求搭好完整引擎后才显示资产。

## 4. 后续版本边界，不阻塞 v0.1

- v0.2：最小无窗口资产 CLI、JSON 结果/退出码、批处理与验证报告。完整 Agent schema、重试收据和常驻服务继续后置。
- Linux：现在检查架构与核心构建，v0.2 复验无窗口资产流程，v0.3 取得具备条件的 NVIDIA 图形实测。macOS、portable Gaussian、Dawn/WebGPU 和 Web UI 后置。
- addon SDK、动态库、热重载、插件市场。
- v0.2 必交 Asset Factory 切片：有界 repair、一级 LOD、凸包碰撞代理、单资产 USD 与源/派生对照；不作为开始混合渲染的前提。完整 scene USD 与 Isaac 为 P1。
- v0.2 必交真实采集 → 外部 COLMAP/GS → WorldForge 的复现流程，早期先验证可行性。自研训练器、ROS2、控制与物理求解后置。
- 动画/骨骼、复杂 glTF 扩展、透明 Mesh 排序、统一重光照、自动 UV 修复。

## 5. 验收脚本

1. 从 Windows 发布目录启动 Studio，导入 GLB 并检查材质/层级。
2. 导入已有 Gaussian PLY，手动对齐坐标、尺度和位置。
3. 添加/移动 Mesh，验证其位于 Gaussian 前、后与相交处的显示，切换表示与调试模式。
4. 关联一份已有碰撞代理和语义，确认碰撞显示独立，不宣称已经仿真。
5. 保存项目并退出，复制项目目录、使原始导入文件不可访问，再重开；资产、变换、表示开关与元数据一致。
6. 导入损坏文件、取消任务、尝试失败保存，确认有诊断且旧项目仍可恢复。
7. 运行固定相机轨迹，记录帧时、显存及已知伪影；按 ROADMAP 的测量条件验收。

通过 Windows 包和以上场景后可发布 v0.1；不等待完整 CLI 或 Linux 桌面包。面试前还须完成 v0.2 资产/采集链路与 v0.3 CUDA 优化/跨平台证据，不能以 v0.1 通过宣称新 P0 全部完成。计划日期由 ROADMAP 维护。
