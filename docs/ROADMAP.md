# WorldForge 开发计划

修订日期：2026-09-19。状态：P0 桌面框架核心已实现并通过本机 Release/CPU/GPU smoke，完整首期尚未完成。
投入：每周 15–20 小时；2027-01-31 前完成可复现的展示版本。

## 1. 当前最高优先级

**先发布 Windows 版本：桌面框架 → Mesh 系统 → Mesh/Gaussian 混合渲染 → 世界资产闭环。性能按瓶颈穿插，CLI/Agent 在主功能稳定之后，多平台后续再做。**

此顺序替代此前“首期三平台 + Agent CLI”以及“先完整资产优化、再混合渲染”的排期。保留服务、表示与平台边界，不提前实现所有扩展设施。

世界资产闭环在首期指：导入 Mesh 和已有 Gaussian → 检查与空间对齐 → 在同一世界中编辑和显示 → 关联可选碰撞代理与语义 → 保存可搬移项目包 → 关闭后重开复现。USD/仿真消费属于后续交换能力，不是首期闭环的前提。

## 2. 技术路线

- C++20、CMake、Windows 11 x64 / MSVC；SDL3 + Dear ImGui docking。
- Windows 后端使用 OpenGL 4.5 / GLSL 450、GLAD、GLM；不再为尚未实施的 Mac 限定 GL 4.1 公共能力。
- GLB 读写使用 tinygltf，项目采用 JSON manifest 与相对路径资产包。
- Windows/NVIDIA 优先实现 CUDA Gaussian provider，Mesh 路径独立于 CUDA。非 CUDA Gaussian provider 随后续需求实现，不阻塞当前混合渲染。
- Core/Domain 不依赖 UI；可变业务通过 Service/Command 修改。仅抽象实际使用的图形资源、任务与 IO 边界，不建设完整多后端 RHI 或公开插件 SDK。
- 依赖固定提交/版本；源码扩展继续参考 usdtweak。详细边界见 [ARCHITECTURE](ARCHITECTURE.md)。

| 阶段 | 目标时间 | 必须交付及退出条件 |
| --- | --- | --- |

| P1：Mesh 系统 | 9/28–10/11 | 静态 GLB、实例/层级、PBR、场景树与变换编辑、基本调试视图、基础校验、Mesh 项目保存重开 |
| P2：混合渲染 | 10/12–11/01 | Gaussian PLY、CUDA 基线、统一相机/变换/线性深度、前后遮挡与相交样例、Mesh/GS 显示切换；已有 Mesh 场景可加入 Gaussian |
| P3：世界资产闭环与 Windows 首发 v0.1 | 11/02–11/22 | 对齐与组合、可选代理/语义关联、源资产打包、混合项目搬移重开、失败处理、可分发 Windows 包和演示；按 PHASE_1 全流程验收 |
| P4：主功能深化与 CLI/Agent | 首发后，目标 11/23–1/10 | 按业务需要补 LOD/比较、资产处理、USD 子集与批处理；随后用稳定 Service 实现 CLI 的发现/JSON/退出码/项目操作，脚本验证 |
| 发布收敛 | 1/11–1/31 | 修复、英文构建/使用说明、样例、性能实测报告、3–5 分钟演示；不临时扩大主功能 |
| P5：源码 Addons | 主功能与 CLI 稳定后，独立排期 | SDK、处理器/命令/面板扩展和示例，先在 Windows 验收；不要求先完成多平台 |
| P6：多平台客户端 | Windows 发布后，独立排期 | Linux/macOS 构建、图形后端与非 CUDA 路径、各平台打包与运行验证 |

P0–P3 合在一起是首期，不用“窗口能打开”替代产品交付。日期是目标，阶段按依赖和实测推进；P0/P1 后重估，首发不等待 P4–P7。P5 与 P6 各自具备条件即可启动，不要求插件先于移植；表中排列体现当前优先级，不构造不必要依赖。

## 4. 性能贯穿主线

- P0 起记录帧时和基础资源统计；P1 观察大 Mesh 导入、上传和显存。
- P2 增加 Mesh/Gaussian 分段 GPU 计时、可见数量、排序/混合开销。
- 出现交互卡顿、显存不足或导入停顿时，先记录固定复现条件，再修正对应瓶颈；不等待独立“性能阶段”。
- CUDA 功能基线与 CUDA 优化区分：先得到正确混合图像，再做布局、剔除、排序、调度优化。不为首发强制完成一套泛化 benchmark CLI。
- 保留基线、相同资产/相机/分辨率/画质条件和 P50/P95 数据；不预设提速比例。成熟后整理为可复现实验报告。
- P2 有首个正确混合场景后锁定演示资产、分辨率和相机轨迹，在本机 RTX 4070 Ti 12GB 上建立帧时/显存基线与交互目标；不在尚无实现时凭空承诺 FPS 或场景规模。首发前必须记录实际数量、设置、测量结果和必要优化，不能偷偷缩减数据掩盖性能问题。

## 5. 首发范围与后续能力

首期详细范围见 [PHASE_1](PHASE_1.md)。LOD、完整优化/对比工作流、USD、批量生产都保留，但不作为开始混合渲染的前置条件；仅在具体场景确有需要时提前实现最小处理能力。

CLI/Agent 协议草案保留在 [CLI_SPEC](CLI_SPEC.md)，P4 再落实。当前只保留可调用的业务服务，不提前做完整 JSON Schema 注册表、幂等收据、跨进程控制或常驻任务宿主。

多平台、源码 addons、Web 与 Dawn 保留演进方向，不是 Windows 发布门槛。首期不用为 Mac 实现 portable Gaussian，也不需要 Linux/macOS CI。新增 NVIDIA 限制必须在 Windows 发布说明中明确；不能泛称所有 Windows GPU 均可混合显示。

## 6. 验证与交付约定

Windows CI 编译 Studio、执行 CPU 测试；本机图形/GPU 验证覆盖导入、渲染、编辑、混合遮挡、保存重开、项目搬移与发布包。缺失/损坏资产和 GPU 不可用要给出可定位诊断。未来平台分别验收，不用 Windows 结果代表其他平台。

自有代码默认 MIT，样例须允许再分发，第三方依赖保留声明。训练、重建、机器人控制、ROS、多用户协同及自动通用资产修复都不进入首期。

P0 的窗口、停靠 UI、真实 GL 视口、示例对象/相机、日志和基础统计已实现；构建/运行见 DEVELOPMENT.md。下一步为 P1 的真实 Mesh 数据与导入，P0 预览不代表世界资产首期交付。
